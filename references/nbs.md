# NBS 编码与播放

## 实际音高

默认本机 Minecraft Java 原版采样映射：

| ID | 名称 | 采样 MIDI 基准 |
|---:|---|---:|
|0|harp 钢琴|66|
|1|bassattack 低音|42|
|2|bd 底鼓|66|
|3|snare 小军鼓|66|
|4|hat 点击|66|
|5|guitar 吉他|54|
|6|flute 长笛|78|
|7|bell 铃铛|90|
|8|icechime 风铃|90|
|9|xylobone 木琴|90|
|10|iron_xylophone 铁琴|66|

|12|didgeridoo 迪吉里杜管|42|

`key = sounding_midi_pitch - sample_base + 45`；播放采样倍率 `2^((key-45)/12)`。不要直接把 banjo 的 key 拷给 bell，否则升高两八度；也不要把 NBS 软件显示的统一键盘标签误当作所有采样的实际音高。资源包改变基准时必须重新校准，不能沿用此表。

存储 key 0–87；原版生存模式音符盒常见范围 key 33–57 是另一层约束。项目允许不限音域时不做 33–57 折叠，但不能越过格式范围。

## 层与力度

- `game`：每音 velocity=100；按 source/role/instrument/volume/pan 分桶建立层，tick 冲突增加平行层。层数多主要是力度分层。目标若只支持层音量，这能保证文件中实际响度生效。
- `nbs`：层音量100，逐音 velocity 存力度，可写 cent 微调。
- 同时相同音高音色是独立概念。`audit` 检查同 tick/instrument/key/fine 重复；`diff` 忽略物理层号，比较起音/音色/key/微调/力度/声像/层音量。
- 轨道100%不代表各乐器同等响亮。铃铛/Pling/班卓和钢琴/吉他要按真实采样、音区、密度评估。默认不叠多个同色同音轨来放大。
- 声部不单独归一化；总音量默认1；Web Audio 混音可能超0dBFS，WAV导出会检查并拒绝削波结果，要求显式降低音量。浏览器的采样峰值检查不是真峰值或LUFS检测，后者用 FFmpeg 分析导出的 WAV。

## 时间和格式

MIDI 变化 tempo 先转绝对秒，再落到固定 tps 网格。默认50tick/s，最大半格误差10ms，不是歌曲BPM。NBS v5 length为16位，过长曲目需显式降低tps/拆分，工具拒绝溢出。

写入NBS v5；读取v0–v5。game元数据默认ASCII，避免某些Java解码器逐字节读字符串造成乱码；UTF-8标题可选择nbs配置并验证目标。

本工具不修改服务器解码器。游戏 profile 仅保证已知层音量策略；循环、微调、声像、范围和自定义音色支持需要针对实际游戏版本验证。浏览器按单次完整曲播放，不自动执行NBS循环。

自定义音色：解码和审计保留定义。浏览器需要音色包中额外提供 `custom_file` 与NBS自定义file严格匹配的采样，缺失时明确报错，不能悄悄用钢琴替代。默认编码器只写16种原版音色。
